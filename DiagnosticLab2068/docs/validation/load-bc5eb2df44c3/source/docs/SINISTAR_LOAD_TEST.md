# Configurable Sinistar load-test suite

Design recorded October 13, 2026; now implemented in the **cartridge edition**. Physical validation is pending. This suite is separate from startup, Full and the default stackless RAM soak. The HOME U16 edition retains its reduced coverage; L shows unavailable there.

## Current implementation and operator controls

Power-load update: **P** selects all loads, including expanded option6 **Power cycle / video rotation**. Option6 alternates a busier slice and a quieter approximately20ms ROM wait. Busy slices interleave the selected RAM, banking and IRQ loads; option3 rotates documented modes0/2/6 (normal/ECM/high-resolution), while quiet slices restore normal mode and inhibit IRQ. With option7 enabled, busy slices write/readback R0–R13, alternate maximum15 amplitudes with16 envelope amplitudes, select triangle envelope10, and emit64 bounded beeper toggles. Quiet slices mute AY and lower the beeper. Disabling option3 prevents video rotation; disabling option7 prevents these audio writes/toggles. Power cycling itself cannot establish increased current or a power-rail fault; physical current/voltage measurements remain necessary.

During power cycling, each verified address-hash read additionally writes/compares00/FF/55/AA and restores its address-derived value. This gives dense switching traffic over all RAM outside the deferred IRQ sink. These additional writes do not alter the standard March elements. The old option6 access-spacing-only behavior is replaced by quiet/busy cycling; with6 disabled, the original synthetic13-register Speech2AY-style behavior remains. Busy cycles skip the extra AY pacing wait; no calibrated frame-rate claim is made.

After S or confirmed R, the page explicitly says **TEST STARTED / RUNNING**, **Load test is active**, and **Next RAM batch starts in6 sec**; yellow border indicates test activity and blue indicates a quieter slice. The page explains that RAM checks overwrite the screen. Cancellation remains armed only after all-key release, and the six-second notice is preserved.

Transient fault correction: load recovery now consumes the already observed mismatching byte rather than rereading RAM. Fault injection verifies exact expected-XOR-observed masks for every D0–D7 bit and multibit26h at4040h/8040h/C040h, as well as the original D1 audio-stack cases. Chip-path reports remain suspects, not component verdicts. This supersedes previous emulator checks that reached the report entry without asserting the actual transient bit mask.

The interface groups **Duration: N One / C Continuous** above **Begin test with:**, followed by **S Start: safe IRQ checkpoints** and **R Start: real IRQ returns**. The selected duration phrase is green. Option4 is labelled **IRQ: 60 Hz screen interrupts**; S enables them in bounded inhibit/arrival windows, while the separately confirmed R profile uses genuine interrupt returns during its foreground burst.

Main-menu **L** opens Load test. Green rows are enabled; white rows are disabled. Release all keys between choices. Keys1–8 toggle RAM address data, March C−, ECM, frame IRQ entry, DOCK banking, normal-refresh access spacing, AY and stack-data comparisons respectively. **B** selects RAM/March/stack baseline83h; **A** enables allFFh. **N** selects one batch (green N marker); **C** selects continuous operation. **S** starts the safe profile. **M** returns. No selection changes startup or Full.

**R** opens the exposed IRQ-return warning. Release R; another **R** confirms and starts. **T** toggles IM2 (green T marker); IM1 is the default. The return profile forces IRQ on, requires a fresh inhibit/arrival pass before entering its return code, and freshly qualifies its state/stack/table bytes. A failed prerequisite skips that return burst and reports. A late saved-PC or trampoline fault can still prevent recovery. The safe S profile never RETs through RAM. Both modes retain a register-only outer scheduler.

The initial and between-batch notices last six nominal seconds and show a16-bit completed-batch count, wrapping at65536. They say **Press any key to stop test**. Active cancellation requires all-key release followed by a new key, polled at256-byte boundaries and within the notice; a stuck contact prevents arming. N ends after one completed batch even if input is stuck. Stopped output gives the count and waits for a new key. RAM faults immediately use chip/bit reporting; auxiliary banking/AY/IRQ failures use existing families4/5/7 and bounded mute/recovery. A stopped or completed batch is only a statement about covered comparisons, not a whole-machine certification.

Implemented workloads:

- RAM: write/read `high(address) XOR low(address) XOR5Ah` over4000h–FFFFh. March: the six specified elements over the same range. The basic IRQ saved-PC sink atBFFDh/BFFEh is excluded from concurrent patterns, then explicitly compared with00/FF under DI at every phase end; it is not claimed to receive concurrent March ordering coverage. No writable scheduler variables are reserved or exempted.
- Every256 bytes, restore ROM4 and interleave enabled loads, retaining the target pointer in IX and the phase in I. ECM keeps SCLD mode2 fetches active during RAM work; status drawing occurs only after comparisons and restores mode0. Banking executes fixed D1h/51h/19h/91h masks (ROM0/ROM4 resident), checks chunk7/6/3 markers and ROM write isolation, then restores11h; low RAM bridges use01h to expose all48K. This does not sweep every possible banking family or transfer execution into other chunks.
- AY: continuously changing, synthetic16-frame Speech2AY-style records, exactly R0–R12 per update with meaningful-bit readback; fixed counts/table addressing and R7 upper bits clear keep port A input. Frequent writes include tone/noise and three amplitudes. R13/R14/R15 are untouched. Without IRQ, a bounded approximately20.4ms ROM delay paces each update; with safe IRQ, updates follow frame arrival. This is traffic/output load, not original Sinistar speech or a sample-identical replay. Listening is still required. The refresh-spacing toggle adds another bounded approximately20.4ms ROM instruction interval per slice; ordinary Z80 refresh stays enabled, with no electrical refresh-margin measurement.
- Safe IRQ: IM1 inhibit/arrival checks use a ROM vector and hardware PC writes toBFFDh/BFFEh, followed by a fixed JP checkpoint and SP reset. IRQ is enabled in bounded ROM windows between256-byte RAM slices; there is no arbitrary RAM-work resumption. Missing or unexpected IRQ reaches family7. When all RAM/stack algorithms are disabled,16 load-only slices still run, so AY/IRQ/banking/spacing can be exercised independently.
- Stack data: sweep every HOME RAM byte in pairs with real PUSH DE / POP BC, checking both bytes against address-derived complementary data including D1-rich values. No popped data selects PC/SP/continuation. Loads run between256-byte groups, not between a PUSH and its matching POP. Failure uses a fixed ROM JP and discarded SP. This catches actual stack bus-cycle data errors without reading a return address.
- Exposed return profile: at each batch end, run a separately qualified bounded foreground write/read burst at5F00h with real frame IRQ saves/restores, aBFFFh foreground stack and5ED0h audio stack. The handler stores/checks saved SP at5E70h, uses a fixed validated restore, checks a mapping shadow at78DFh, performs optional AY and D1h/51h bank reads, updates/checks5E72h frame data, then POP/EI/RETI. Arrival is also held in a CPU register, so corrupted RAM frame data cannot fabricate an arrival. Optional IM2 builds/readbacks257 bytes at7A00h and a JP at7B7Bh; these bytes and the narrow trampoline are the only HOME opcode exposure. IRQ returns do not overlap the destructive full-range March sweep, preventing self-corruption of their state. ECM/AY/banking can overlap the interrupting foreground burst. A safe test result does not certify this narrower return-dependent profile.

Control locations: `src/load_low.asm` (ROM0 bridges/recovery/data PUSH/POP) and `src/load.asm` (8400h optional ROM4 scheduler/IRQ handler; asserted below8C00h). To fit the module, fixed generated keyboard scanning now resides atE000h–E599h in ROM7; low-ROM paint/exit helpers preserve D/E/IX/AF' and restore01h. No HOME keyboard buffer becomes code or control. Both images still build; HOME keeps its scanner in its HOME ROM and omits all new load routines.

Evidence: `scripts/verify_load.mjs` executes all256 safe slice option masks, representative complete batches, real PUSH/POP D1 loss in all RAM regions/audio-stack vicinity, timeouts, bank/AY failures, input controls, one-batch count, lost UI writes and real IM1/IM2 returns. Image-bound results and source copies are retained under docs/validation. These are emulator results, not a reproduction on the reported machine. First RAM address/expected/observed/phase/region error masks are register-held; auxiliary faults retain class/address-or-register/expected/observed/phase. Completed batch count is shown only for no-fault stops; RAM first-fault fields replace its registers. There is no persistent configuration/history log or fault-time batch counter. Random seed variants, true electrical timing/refresh measurement, all legal mapping families and exact game/audio replay remain future work.

The sections below preserve the design baseline; where they propose broader coverage, the implementation above defines what is executable today.

## Report motivating the tests

The user reports corrupted game state on a real TS2068 running Sinistar: a byte pushed to the stack read back with D1 lost. The same machine passed March C− over 5F00h–FFFFh in ECM with interrupts disabled, 37 passes, and every bus test performed by the reporter. These are supplied observations, not diagnostic-project measurements. The exact stack address, expected/observed byte, game/cartridge revision, peripheral configuration, test implementations and instrumentation are not supplied. Do not infer a particular failed RAM IC without the address. A D1 error implicates a low-nibble path; shared supply, wiring, timing and control remain possible causes. Suggested 5 V droop under AY load and refresh/interrupt timing are hypotheses.

## What the inspected Sinistar actually does

Read-only source snapshot: `sinistar-load-source-evidence.json`; these hashes describe the current local source, not a claim that it matches the affected machine or the earlier published image.

- `mining-scene.asm:title_boot` uses SP=BFFFh, DECR=02h (ECM), HSR=10h then18h and fills HOME6000h–77FFh. Runtime control/renderer resides in DOCK4. The diagnostic instead needs DOCK0 as its immutable anchor, so its mapping masks must include bit0.
- `start_resume` installs a 257-byte HOME IM2 table at7A00h, filled with7Bh, and a JP trampoline at7B7Bh. It sets I=7Ah, IM2 and EI. Foreground physics/rendering uses CALL/RET and waits with HALT for frames.
- `isr` pushes AF/BC/DE/HL on the interrupted foreground stack, selects10h, stores SP at5E70h, changes SP to5ED0h, calls `audio_tick`, then restores SP from5E70h. It may call incremental rendering, restores HSR from78DFh, increments the frame byte7802h, pops registers, then EI/RETI. Saved-SP and saved-mapping RAM are additional failure points.
- `audio_tick` selectsD0h for effects, restores10h, and calls speech/SFX work. `speech_tick` selects50h. Speech writes AY R0–R12 from successive stream bytes using FFF5h/FFF6h; it skips R13 during ordinary frames. The diagnostic's existing envelope demonstration therefore differs from speech traffic. The inspected generated speech selector is50h.
- ECM display fetches, foreground RAM writes, banked reads, frame interrupts, stack saves and AY traffic overlap. Disabling interrupts removes both interrupt stack activity and frame audio updates. The supplied March test also excludes4000h–5EFFh, including Sinistar's audio stack and saved-SP slot.

## Operator options

Proposed entry: a separate **Load test** submenu with numbered toggles, explicit Start, baseline and combined presets, continuous repeat, and optional finite batch count. Store the authoritative option mask and scheduler state in registers. Display copies are expendable data. Display the selected configuration for six nominal seconds before starting; active cancellation still uses all-key release followed by a new key. A stuck contact can prevent cancellation from arming; finite batches must still finish. No automatic changes to the normal Full suite.

| Independent option | Actual intended workload and comparison |
|---|---|
| RAM accesses | Repeated fixed-seed address-derived and pseudorandom write/read bursts, forward/backward, alternating regions and page boundaries; first mismatch stops. Include4000h–5EFFh and all upper RAM. Compare immediately and after intervening loads. |
| March C− | Standard six elements: ascending w0; ascending r0/w1; ascending r1/w0; descending r0/w1; descending r1/w0; ascending r0. Destructively cover4000h–FFFFh through fixed-ROM continuations. Hold interrupt sink/display/state out only during a concurrent batch, then DI and test those bytes separately. Report both concurrent and deferred ranges. |
| ECM | Select documented mode2 and independently exercise4000h–57FFh and6000h–77FFh with alternating/address-derived bytes while SCLD fetches both planes. Compare the same workloads in mode0 as the control. Status redraw only between comparisons, never into an outstanding expected-data range. |
| IRQ arrivals | Repeated IM1 frame arrival into a fixed ROM handler, hardware PC writes to a dedicated HOME sink; handler DI and fixed JP, never RETI. Restart a known bounded foreground slice, resetting SP every time. Sweep interrupted foreground instruction positions. Missing/unexpected IRQ expires with a separate result. This loads entry writes but does not reproduce arbitrary interrupted-work resumption. |
| Banking | Bounded DOCK data-read/signature and HOME write-isolation batches with ROM0 resident. Use equivalents11h/19h/99h/D1h/51h only when live HOME targets remain visible. Never access a hidden HOME sentinel; restore01h before its comparison. Verify affected chunks before using them. Compare stable bank, single-bit changes and multi-bit changes; use immediate OUT(F4h),A as in the game. No EXROM toggles or banked execution transfers. |
| Refresh/access spacing | Normal Z80 refresh stays active. Compare dense instruction/RAM bursts, long bounded ROM instruction loops and varied read/write spacing with mode0/2 and IRQ off/on. Alternate55h/AAh and D1-rich02h/FDh, hold then read. Do not claim measured refresh margins or disable refresh without a separate hardware-specific design. |
| AY load | Independently select I/O traffic with muted amplitudes, steady three-channel output, or frame-paced changing tone/noise/amplitude data. Include Sinistar-like R0–R12 streaming and a separate envelope option. R7 keeps I/O ports input; never write R14/R15. Fixed ROM table, fixed register count, bounded phase count and unconditional mute on every stop/failure. Confirm audible output by observation. |
| Stack data | Explicit register-only comparison of data written using PUSH and read using POP into data registers, never PC/SP/control registers. Walk bits/complements including02h/FDh, rotate bounded sacrificial windows in all three RAM regions; specifically test5ED0h vicinity andBFFFh vicinity. SP derives only from fixed ROM ranges, DI around each PUSH/POP pair, restore fixed SP before any IRQ slice. Repeat readback after ECM/AY/banking work while preserving expected data in registers. Corruption must lead to a fixed ROM JP report, never RET. |

`0F00h–3FFFh` is ROM in this cartridge mapping, not writable HOME RAM. Expose4000h–FFFFh as the RAM range; offer optional ROM integrity reads for the lower requested addresses. Never label ignored ROM writes as a passing RAM test. HOME U16 edition has no DOCK banking option and needs its own reduced implementation/audit; this design does not silently add it there.

## Isolated interrupt-return profile

Register separately as LOAD-02. This is the closest software reproduction of Sinistar's failure, and must require fresh qualification of every vector/table/stack/saved-state byte followed by basic IRQ arrival qualification. Use ROM-owned handler/opcodes, separately selectable IM1 versus qualified HOME IM2 table/trampoline, foreground and5ED0h-style audio stacks, bounded audio work, saved-SP and mapping shadows, genuine register saves/restores and EI/RETI. Audit every mapping for visibility of live state before entry. The normal scheduler/reporter remains stackless.

Qualification and guards cannot guarantee the next saved return address survives. A fault in a saved PC, SP, IM2 pointer or trampoline can prevent recovery before a comparison runs. This exposure must be visible before Start, remains opt-in, and is excluded from default soak/Full. Do not represent the safer IRQ-arrival or stack-data tests as equivalent RETI coverage. No unbounded HALT; ROM instruction budgets bound absent IRQ waits, though corrupted control flow/clock loss remains outside software guarantees.

## Presets, diagnosis and results

Run a baseline with RAM/March/stack data and IRQ/ECM/banking/AY off. Repeat with one load enabled at a time, then ECM+AY, ECM+IRQ, IRQ+AY, and all safe loads. Match the failed machine's accessory/cartridge configuration and record it; compare cold and warmed runs. Refresh/access spacing is a pattern dimension, not an independently simulated refresh circuit. CPU arithmetic/register consistency and repeated cartridge integrity reads are useful separate controls for non-RAM corruption.

At first mismatch latch test/subphase, configuration, address, expected, observed, XOR mask, completed batch count and current mapping in reserved registers. Inhibit IRQ, restore known ROM0/HOME mapping and mode0, mute AY through fixed bounded writes, then enter the existing chip/bit reporter. Preserve the first fault across UI corruption. Distinguish RAM data, stack data, mapping, AY register and IRQ timeout results. A combined failure needs isolated reruns; a passing run does not disprove the reported load-sensitive fault.

For physical replication record the image hash, board/ROM revisions, cartridge/interface/firmware, power supply, speaker/audio settings, duration, presets and exact first fault. A technician can correlate 5 V at the motherboard/AY/DRAM and DRAM refresh/control timing with sound/IRQ workload using the supplied schematic and original technical manual. Software cannot measure supply droop, certify refresh timing or identify a regulator/DRAM component from D1 loss alone.

## Required implementation acceptance

Before marking implemented: audit register ownership and every mapping; verify all option combinations and disabled-load absence; inject D1 loss at stack-data readback, lost writes, late UI/state corruption, absent IRQ, unexpected IRQ, bad bank signatures and absent AY. Verify bounded recovery, mute, all-key-release cancellation and first-fault priority. Bind evidence to the exact built image. Genuine RETI/IM2 tests must document unrecoverable injected saved-PC/table corruption rather than manufacture a safe outcome. Physical cold/warm mixed-load validation remains a separate gate.
