# Version0.2 diagnostic suite

## Full selection and completion

Menu1 now shows an explicit coverage overview; a new1 starts, M returns. F-at-startup remains direct. Complete RAM,100 bank cycles and AY masked register comparisons are automatic; beeper/AY sound, six video cards and keyboard require user observation. After keyboard exit/timeout a summary distinguishes digital matches from unverified observations and lists excluded ROM CRC/IRQ/optional CPU/overnight/external tests. Keyboard timeout is not key certification. Cancel/fault paths do not claim completion, and a held exit chord cannot immediately dismiss the summary. See [FULL_TEST_COVERAGE.md](../FULL_TEST_COVERAGE.md).

## Current boot-path addition

Every boot choice now performs a separate ROM0 register/math/shift consistency check before any HOME writes. Default quick00/FF success then adds16 qualified55/AA opposing address pairs. Boot CPU mismatches repeat8/stage1-3; pair mismatches repeat9/index1-16; qualification data mismatches use the ordinary RAM chip-path reporter. Boot8/9 output uses no display/keyboard and repeats until reset. See [BOOT_PATH_DIAGNOSTICS.md](../BOOT_PATH_DIAGNOSTICS.md) for precise algorithms, ranges, phase48-63 data reports, fault limits and evidence. Optional ROM2 CPU code remains separate. Embedded font bytes moved toDOCK ROM1 at2200-24FF; ROM0 glyph renderers briefly selectHSR03 and restore01. Earlier quick-baseline descriptions below refer to the full48K00/FF portion; no full55/AA sweep was added to quick boot.

This is executable ROM-only firmware, with emulator evidence and physical validation pending. It replaces the three-choice v0.1 menu with a runnable stock-machine suite. It does not implement every advanced module in the research catalog; the registry preserves that distinction.

## Startup and menu

Entry sets DI, DECR40, HSR01 and a blue border. Before testing RAM it performs an additive16-bit integrity comparison over the first8144 bytes of each of the eight cartridge chunks. This detects ordinary changed bytes/read failures but is not collision-resistant and excludes reserved checksum/marker tails. A bad image/read path repeats three white/black border and beeper pulses; R retries. Active opcode-fetch faults can still prevent recovery.

Then startup runs a quick00/FF fill/read sweep over all48K RAM (phases1/2 only). Measured menu entry is426 modeled60Hz frames after direct cartridge entry (about7 seconds),529 frames including native OS launch (about9 seconds); these are not calibrated physical deadlines. Walking bits, March, address planes, random and retention are menu-selected, not automatic startup. A new key press can cancel at safe boundaries; cancellation is not a pass. The main menu states STARTUP CHECK IS LIMITED; reaching it or cancelling startup never means all algorithms passed.

Main menu:

1. Full digital + guided test: complete RAM,100 banking cycles, beeper, AY register comparison plus A/B/C/noise/envelope output, six video patterns in sequence, then keyboard. Sound/video are observations, not automatically verified PASS results. A new key cancels the sequence. Keyboard exits with a held CAPS SHIFT+SPACE or ENTER+SPACE chord, or its finite budget.
2. RAM choices: complete, patterns+walking, March C-, address data, seeded random or write/hold/read.
3. Video choices: labeled normal/BRIGHT bars, standard FLASH/bit lanes, second display, ECM dither, hires calibration,128 attribute mixes. A new key returns; viewers also have a finite software budget. Black is unchanged by BRIGHT; missing extra brightness may be the display equipment. The source Mark Miller credit appears in Help.
4. Physical keyboard layout: both CAPS positions share one closure, BREAK is CAPS+SPACE; press green, released-after-press cyan, unseen white. RAM-held seen flags are optional display data and never control pointers/counts. Hold CAPS SHIFT+SPACE or ENTER+SPACE to exit. This is a live matrix aid, not proof that both physical CAPS buttons were tested separately.
5. Beeper/AY: bounded low/mid/high beeper segments with steady red/magenta/green borders, respectively. Each tone has700 waveform cycles; both high/low FE writes retain that tone’s border color. AY meaningful-bit reads for R0-R13 use index-derived values, then the24-step guided AY playback sequence below. R7 remains input-safe, R14 is not tested as storage, R15 is not probed. All normal/cancel/failure exits mute amplitudes and lower FE.
6. Banking stress: repeat until a new key or first mismatch; pass count wraps modulo65536. Resident ROM0 stays selected. HSR patterns03,05,09,11,21,41,81,FF,55,AB,FD,FB,F7,EF,DF,BF,7F,01 test selected-chunk signatures and ROM write protection, followed by HOME sentinel preservation at5FF0/7FF0/9FF0/BFF0/DFF0/FFF0. This does not prove every byte or the low-anchor unmap transition; optional HOME CRC exercises a separate controlled bit0 transfer.
7. Overnight RAM: repeated complete sweeps;16-bit completed-pass count, any-key cancellation, first mismatch stops and latches register-held fields/pulses. No elapsed-time/temperature claim, no disk log or arbitrary pause/resume. DRAM refresh continues normally.
8. Optional ROM CRC32: H for HOME16K, E for EXROM8K. Show measured CRC and stock reference (BF44EC3F/AE16233A); different means unrecognized, not necessarily defective. Repeat manually to compare stability.
9. Optional CPU/SCLD: U runs the CPU/address module described below; I selects the IRQ test. I checks inhibited IRQ followed by arrival independently of HOME RAM contents. Explicit SP=BFFF is used solely as a sacrificial sink for hardware PC writes; handler jumps to a fixed ROM checkpoint, never reads/returns via the interrupted stack. Failed RAM contents do not invalidate control flow; the CPU bus write cycle must still complete. A green border acknowledges arrival even if text is unreadable. Missing arrival or failed inhibition reaches a bounded result.
0. Help/credits. P selects EAR/joystick raw input observation, not tape block verification. Joystick reads use AY R14 and explicit01F6/02F6 strobes; EAR is00/40. Both have bounded polling and any-key exit.

Submenu entry uses a bounded release gate so one held key does not select both the menu and a test. At the gate deadline, currently held numeric/optional-test keys are recorded in CPU registers and excluded until a new press edge. Other working keys can still select a test; a stuck H/E/I/U cannot silently trigger an exposed test. RAM and timed test stages require all keyboard inputs to read released before accepting any key as a stop press; an initially held key cannot skip them; keyboard mode offers BREAK and a finite timeout. There is no unbounded release wait.

## RAM algorithms and retained fault state

The baseline expansion preserves the v0.1 pattern set00/FF/55/AA/0F/F0/33/CC, walking-one/complement immediate comparisons, and six March C- phases. Complete coverage adds an address-derived hash, separate low/high address-byte fill/read planes, seeded16-bit LFSR data (seedACE1, polynomialB400, period65535; compare high byte), and55/AA write-hold-read phases. Holds use500x3000 instruction loops with M polling; they retain normal CPU refresh. Random comparison stops on its first new mismatch so its register-held LFSR state cannot be confused with the comparison scratch register. This is not a refresh-disabled test or an exhaustive random-seed matrix.

Every pass covers4000-FFFF, including optional UI buffers and display. No stack/workspace exemption. Phase IDs1-30 baseline,31 address hash,32 random,33/34 holds,35/36 address bytes. Default controls do not use CALL/RET/PUSH/POP/RST/HALT or RAM code. Comparison uses fixed ROM IY continuations; alternate H/L/D hold three region XOR unions, alternate E/B/C first phase/expected/observed, IX first address. I holds current phase. Alternate AF holds selection and a carry flag recording all-key release. Each comparison reloads its fixed ROM IY continuation; the shared stop poll preserves the RAM address, loop counters and fault registers. Soak uses alternate BC for the pass count until a first fault replaces it with expected/observed fields; that transition stops rather than tries to preserve both.

Byte-boundary stop checks occur at256-byte read blocks and generated baseline fill blocks; address/random/retention fills are finite and cancellation can wait for the fill to finish. There is no resumable partial-phase state. All deadlines are instruction budgets; CPU clock failure remains outside software control.

## Failure display and codes

RAM faults repeatedly emit a long white sync tone, class2 white/black pulses, chip index1-6 (U6,U7,U12,U13,U17,U18), then nibble bit1-4 or5 for multiple bits. R retries all RAM tests after a reporting cycle. A new key acknowledges the RAM fault and opens the menu for independent tests; leaving the report discards the retained first-address field when loaders reuse IX. This permits audio/keyboard/video and the fixed-checkpoint IRQ test even with RAM faults. Rich text may be damaged; controls stay in ROM. First fault fields remain in registers during reporting; automatic sweep completion can accumulate additional fault bits.

Before each chip report, the renderer draws large attribute-coded RAM FAIL / chip PATH / CODE2 chip-index text. If U6's nibble is suspect, it uses U7's surviving PAPER bits and zero healthy bitmap lanes. If U7 is suspect, it uses U6 INK bits and filled healthy lanes. Upper-RAM reports also adapt to a detected display-nibble fault. If both display nibbles are suspect, it skips text and continues pulses. Stable-nibble contrast is modeled; intermittent/address/refresh/DMA faults may defeat the image. Text indicates a suspect path, not an unproven component verdict.

Other digital mismatch screens show DETAIL family04 banking,05 AY,06 CRC execution-code/gateway qualification,07 IRQ. The same family count repeats as white/black border and beeper pulses independent of text; all keyboard rows are polled between bounded groups. ADDRESS is meaningful for banking; REGISTER/PHASE is meaningful for AY or IRQ (0 inhibit,1 arrival); other fields may be unset. Bank failure records the first offending signature/sentinel address and restores HSR01. CRC data mismatch prints measured identity rather than the hardware-failure page.

## Optional execution exposures

HOME CRC first compares512 high-ROM bytes with the separate ROM1 shadow. It maps low+high11, jumps to8020, and only then removes low ROM by HSR10. The high code reads HOME0000-3FFF with the standard reflected CRC32 polynomialEDB88320, restores11 and jumps to a fixed low continuation. Missing high ROM during execution can stop it despite qualification.

EXROM first performs the same high-code comparison, then copies/checks a256-byte gateway at HOME C000. The gateway executes in HOME, selects DECRC0/HSR01, measures EXROM0000-1FFF, restores DECR40 and jumps into low ROM. Corruption of gateway opcodes during execution can prevent recovery. It is separately selectable and never part of automatic Full test or overnight RAM. The IRQ test likewise remains separately selectable, although it does not rely on RAM holding a return PC. External NMI is not a supported cancellation mechanism.

## Optional Z80 and address-path module

From main menu9 press U. This explicit, destructive test runs from fixed DOCK ROM2 (HSR05); the low-ROM bridge temporarily selects HSR01 to access HOME data, then restores05 before jumping to fixed4003/4006 stubs. Execution never transfers through RAM or a saved stack. CPU entry4000, failure4003 and alias continuation4006 are a maintained ABI. ROM2 code must fit4000-43FF; packed assets may occupy4800-5FCF. The builder checks the boundary. This module is excluded from automatic startup, Full and overnight RAM.

Five stages compare selected Z80 behavior: (1) complementary patterns in B/C/D/E/H/L, (2) 8-bit arithmetic, carry/zero/sign/overflow examples, logical operations and16-bit ADD, (3) rotates/shifts and BIT/RES/SET, (4) EXX and AF/AF' transfer/retained carry, and (5) IX/IY increment/decrement and byte values using the original NMOS Z80 IXH/IXL/IYH/IYL operations (not part of the original documented instruction set). It is a consistency subset, not an exhaustive instruction/flag certification. I retains the stage number; no SP initialization or stack access occurs. Stages overwrite working and alternate registers, so previously retained RAM-fault fields are discarded.

Before stages1-6 the existing stackless reporter emits8 white/black border/beeper pulses, a longer gap, then the stage number (stage6 is address probing). On a detected CPU mismatch it repeats family8 followed by stage1-5. On a detected alias/data mismatch it repeats family9 followed by bit index1-16:1 means A0 and16 means A15. A key exits a repeating fault; a successful run opens the matched-results page. These CPU failures deliberately use register-only pulse reporting rather than a rich RAM display. If a stage stops execution before detection, the last preceding checkpoint is a clue, not proof of the failed instruction. Count groups by their longer gap.

The address test probes each of16 address-bit pairs with55/AA, then reversedAA/55, reading both endpoints after each pair of writes. The base is4000 except A14 uses8000 to keep both endpoints in HOME RAM. A15 compares4000/C000. The fixed ROM bridge preserves the DE address mask and I bit index. It stops at the first mismatch. It does not distinguish a stuck global CPU address pin from a RAM-side multiplexer/decoder, solder joint, or bad data storage: report a suspect address/data path. Existing full48K address-derived tests provide broader coverage; these16 pair probes add localization, not a replacement or proof of every address connection.

Survival requires CPU clock, instruction fetch, control branches and enough reporter register/ALU operation. A global data-line fault may corrupt opcodes; a global low-address fault may alias the code; an IY/B/HL/flag fault can defeat reporter or loop control. Entering ROM2 exposes its opcode path. No software timeout guarantees recovery after a CPU stops or corrupts its own loop/branch. Passive HOME startup still applies. These tests do not exercise CALL/RET, interrupt returns, WAIT/BUSRQ recovery, physical refresh waveform generation or pin-level timing. Such paths need separately exposed tests or an external instrument.

## Revised exit controls

RAM/soak, timed video/audio/banking/input stages accept any key after observing all40 matrix inputs released; polling preserves RAM pointers/counters and fault fields. An initially held/stuck key cannot skip the sweep, but if any contact never releases, this broad stop channel cannot arm. Finite tests still finish; an indefinite soak/bank loop may then require external reset. Main and selection submenus retain their choices and M back control. Result/peripheral-fault/CPU-fault pages accept any key; a permanently held contact may acknowledge them. RAM faults retain the guarded stop channel and R retry priority. The keyboard remains special: hold either CAPS SHIFT+SPACE (BREAK) or ENTER+SPACE for64 scans, with a finite scan-budget fallback. Host escape-key behavior is emulator-specific; ENTER+SPACE uses the emulated matrix directly.

## ECM Sierra Lite gradient and disc

The mode2 card now combines a diagonal corner-to-corner hue/value gradient with a hue disc whose saturation increases toward its rim. Bottom strips preserve all regular/BRIGHT palette codes. ## Quick power-on policy

Selection8 is internal startup-only: cartridge integrity still runs first, followed by full-address00 fill/read and FF fill/read. The generated RAM code checks selection8 at the fixed phase2/3 boundary and transfers to the existing tests_done reporter/menu path. Manual Complete/Full selections0/7, patterns1, March2 and other selections retain their previous algorithms. No walking/March/address/random/hold work occurs automatically. A new R press on a RAM-fault report still selects the complete RAM test explicitly after all-key release; holding the startup key cannot repeatedly retrigger it.

A new key after all-key release interrupts startup at the existing256-address safe polls. Partial failures already found are reported, not discarded as a clean cancellation. Initially held/stuck inputs cannot bypass startup; without keyboard input the quick sweep finishes or reports faults. Persistent stuck data bits and lost writes are covered, but uniform00/FF sweeps do not establish address uniqueness, detect every bit bridge/coupling fault or qualify retention/thermal behavior. Use RAM Complete or Full for those checks. The menu display and bounded keyboard handling provide observable bring-up behavior; they do not automatically certify analog video or that every physical key works. CPU control/reporting remains stackless low ROM even when the quick test is interrupted or fails.

Fuse's completed-startup RAM checkpoint now expects phase2 (02 hex); historical complete-startup evidence expected34 (22 hex). The current TSRun RAM verifier independently checks34 scenarios:28 quick-startup cases and6 explicitly complete-sweep cases, records completion/early-fault phase, all-HOME accesses and unchanged SP. Complete runs with a detected fault may stop in random phase32 by design. The main verifier also checks quick-startup exclusion of extended phases and Q cancellation. The colorbar generator's I/G glyph mapping is corrected; source labels were spelled BRIGHT, but the old glyph table rendered BRGIHT.

## Expanded AY playback and visual guide

AUDIO menu2 first runs the existing meaningful-bit, index-derived R0-R13 register readback. A mismatch still reaches family5 with the register index and mutes output. On a match, the new guided page highlights an8-cell sound label in yellow; completed progress dots turn green. Four ascending pitches (periods1000,500,250,125) run on A alone, then B alone, then C alone. Adjacent pitches are octave steps; corresponding pitches across channels should match. Labels LOW/MID/HIGH/TOP avoid implying an independently measured frequency.

Next: fixed volume3/8/15 on A; A-only noise periods31/8/1; A-only envelope shapes9 falling then holding low,13 rising then holding high,10 alternating triangular,8 repeated falling sawtooth; all-channel chord with periods500/400/333 and amplitudes12; final silence. Envelope period is0800, with320 bounded hold loops per step (approximately one modeled second, not a hardware timebase measurement). There are24 steps. Individual analog outputs, logarithmic volume differences, clock accuracy and the analog path require listening; register readback alone cannot certify them.

Each step first mutes amplitudes and sets R7=3F. Low-ROM code selects HSR05, reads one fixed16-byte ROM2 table entry at4400+16*I, and writes R0-R13 with the existing meaningful-bit masks. R7 masks out bits6/7 so port A stays input; R14/R15 are never written. It then restores HSR01 before accessing display RAM. I is the independently bounded0..23 step counter; it never comes from the table or HOME. Two table coordinate bytes are display-only: row&15 plus6, column&18 hex. Thus a damaged table cannot choose an opcode pointer, register index, loop length or arbitrary memory destination; highlight writes stay in the attribute plane. HOME contains display/progress only. Key stop remains guarded by all-key release and runs fixed mute recovery. Even losing all HOME writes does not change playback/control.

ROM2 now reserves4000-43FF for optional CPU code and4400-457F for the384-byte AY table; packed source assets start4800. Builder and CPU assembly enforce the boundary. Table definitions, step names, register values and highlight coordinates are recorded in manifest. AY failure reporting remains family5; this playback sequence does not invent automatic analog PASS results. Full runs this sequence then video, with the same mute boundary.

`node scripts/verify_ay.mjs` verifies actual24 step register values, highlight/progress bytes, period/volume/noise/envelope variety, key cancellation and muting at8 representative steps, corrupt-table bounding and all HOME writes lost. Existing core/Fuse/fault checks remain required. Actual active-screen capture is ay-listen-active-v02.bin, decoded to ay-listen-active-v02.png when packaging.

## Startup selection, progress and CPU-code guide

After cartridge integrity, held R selects complete RAM (selection0) and held F selects the normal Full digital+guided sequence (selection7: RAM,100 banking cycles, beeper/AY, six video cards and keyboard). No held key selects quick00/FF (selection8). The probe requires the all-row low5-bit value17 hex, then the specific F or R row also17: an all-low matrix or another pressed column is rejected. F has priority when both same-column R/F contacts are low. An isolated stuck R/F cannot be distinguished from an intentional hold and may select the longer run; counts remain bounded, and no release wait blocks execution. Release the selection key/all contacts before pressing a new key to stop. Explicit CPU/ROM/IRQ exposure tests remain separate from Full. Hold through power-on until the selected startup page appears; this firmware samples after integrity, not at the hardware reset instant.

A finite approximately1.2-second status notice precedes the RAM sweep; the extended page highlights R/RAM-only or F/Full. Startup helper code uses spare low ROM0069-00FF, after fixed0038/0066 vectors; its size is asserted and the LROS entry remains0100. Normal fonts/status data are copied from cartridge ROM with bounded decoding, even if screen RAM corrupts. The display is then overwritten by RAM algorithms; status drawing never changes bytes under verification mid-sweep. Border phase colors: blue1=patterns, cyan5=walking bits, yellow6=March, magenta3=address planes/hash, green4=random, red2=retention. Error pulse groups override these steady colors. This distinguishes phases, not a byte-level percentage; progression still needs functioning SCLD border output. R fault retry now requires the existing all-key release guard, retaining repeated reporting with the startup key held.

Menu9/U now draws a cartridge-supplied CPU guide before execution. Expect one pair of groups per stage:8 pulses then stage1..6;1 registers,2 arithmetic,3 shifts/bits,4 alternate registers,5 index registers,6 address pairs. Success opens MATCHED. A detected CPU inconsistency repeats8/stage1..5; an address/data-pair mismatch repeats9/index1..16 (A0..A15). Border and beeper use the same counts. Repeating a stage differs from the normal sequence advancing to the next stage. If execution stops before its checker/reporter can act, the last checkpoint may narrow the search but cannot certify the failed part. A global line affecting cartridge opcode fetch, or a damaged CPU register/branch used by the reporter, can stop both checking and reporting. A RAM-side address alias may be detected while ROM execution survives. The guide stays visible where display RAM works; it does not depend on that display for control.

The unhelpful main-menu RAM-destructive wording is replaced by quick/full selection guidance. Memory overwrites remain documented here as an implementation fact rather than presented as an operator warning.

## Font and absent-HOME-ROM dependency

The build copies stock U16 font bytes3D00-3FFF into768-byte font_data embedded in cartridge chunk0. All normal text and hex rendering uses that low cartridge address, not live HOME ROM or its routines. Large RAM-failure attribute lettering is also supplied by cartridge data. UI buffers are optional HOME data with clamped characters; no font pointers or execution continuations are recovered from RAM. A bad installed TS ROM font cannot alter these embedded glyphs after entry.

Passive LROS discovery still requires HOME startup. The present DCK/raw image is not a standalone reset-ROM image and has not been tested without a TS ROM installed. Future Pico hardware could provide independently decoded boot code, correct /BE/arbitration and a distinct reset entry at0000 before HOME initialization, reusing the embedded font and stackless tests. This needs a separately validated hardware/firmware boot profile; merely loading today's LROS image into a PicoROM does not establish that capability.
