TSPico v1.00, v2.x and disk storage

The same dual-protocol cartridge can boot on original TSPico 1.00 or a supported TSPico v2.x interface. It selects the transport from a validated handshake. TSPico firmware, the TSPico ROM extension and the separate PicoVideo display firmware are different components; upgrading one does not upgrade the others.

The TSPico v2.x implementation was inspected against firmware 2.3.1 / ROM 2.3. These features should not be inferred from every firmware labelled 2.x, or from the board revision alone. Direct SD and native-directory mode require the supplied optional CP/M service; the cartridge package does not install firmware automatically. See the firmware feature matrix and startup guide.

Why use TSPico RAM?

CP/M needs writable low memory. This implementation uses 32KiB of writable DOCK memory alongside upper HOME memory, giving programs a 52,992-byte transient program area. Separate TSPico SRAM holds the disk: twenty 8KiB pages for 160KB, or forty for 320KB. A small resident driver switches disk banks and copies sectors without mapping away the running code or stack.

A RAMDisk is fast working storage, but volatile. Saving a game or editing a file changes the CP/M disk in SRAM; on the RAMDisk path, TPSAVE is the additional step that preserves that disk on the SD card. Existing saved disks take precedence over the factory preload, so replacing preload TAPs does not replace an older saved session.

Oliger disk files and exchanging media

The project supplies standard single-sided 160KB and double-sided 320KB Oliger-compatible .DSK containers, complete CP/M disk .TAP containers, and Python tools for creating disks, copying files and converting between containers. The filesystem bytes are shared across these formats; a cartridge must match the image geometry.

Fuse with the JLO/Oliger interface and the TSRun disk adapter use DSK images. TSPico v2.x with the optional CP/M service can mount compatible DSK/TAP files or expose native files. Original 1.00 reaches the same disk contents through TAP-backed RAMDisk loading and explicit saves. This is disk-image and filesystem compatibility; TSPico is not emulating the Oliger controller hardware.

The 320KB browser player keeps the game disk on A: and the utility disk on B:, with separate open/download controls. TSPico currently exposes one mounted CP/M drive, A:. Save your work before changing its volume. See disk tools and the worked save/reload session.

64 columns, or 80 with PicoVideo v4.2

A standard TS2068 runs the ROM-independent console in 64 columns by 24 rows, using its 512-pixel high-resolution display. The ordinary TSRun player also uses this 64-column display.

With the supported PicoVideo v4.2 hardware and firmware, CP/M detects the text renderer and selects 80 columns by 24 rows. Startup reports PicoVideo 80 column mode enabled. COLUMNS 64 and COLUMNS 80 select the renderer; exit and restart applications after changing width so they read the new setting. Disk contents and the selected colour scheme are preserved.

PicoVideo is optional and independent of the TSPico storage protocol. Older published V4 firmware does not implement the same usable 80-column renderer and can capture banked DOCK writes as display garbage. The v4.2 implementation distinguishes HOME display writes from banked memory traffic. See the PicoVideo setup, compatibility and rollback guide.

Which font does it use?

The public 64-column cartridge uses Daniel Hepper's public-domain font8x8 basic Latin bitmap font, selecting characters 32-127 and converting their bit order for the TS2068 console. It does not contain a font extracted from the TS2068 HOME ROM. That is why its lettering differs from the familiar BASIC screen.

In 80-column mode, character codes and attributes are drawn by PicoVideo's text renderer using the font built into its firmware. That font can differ from the cartridge's 64-column bitmap font. A local build can optionally use a privately supplied TS2068 ROM font; the public downloads retain the public-domain font.

What this work added to the AI development skills

The CP/M work also produced reusable guidance in the TS2068 AI skill collection. These are development instructions, references and helper assets for future projects; the complete CP/M implementation remains the worked example, rather than an implied capability of every baseline library.

  • Using TSPico SRAM: the TSPico and cartridge-development skills now document MEMDOCK slot selection separately from CPU F4 banking, safe placement of code/stack/workspace, 8KiB page transfers, RAMDisk geometry, preservation of the visible screen, and explicit save/reload. The CP/M slot allocation is documented as an example, not a universal reservation for every program.
  • Choosing the correct protocol: the TSPico storage protocol is documented for both v1.00 and v2.x, allowing cartridges to implement TSPico-based storage directly without relying on BASIC or ROM routines. Supported v2.x firmware is preferable for new cartridge projects because it provides raw-file and directory channels, buffered sequential reads and bounded file writes, giving applications more flexible SD-card access than v1.00's TAP-based transfers. The skill explains the original v1.00 shared FIFO and the v2.x status-register/channel interfaces. It covers positive protocol detection, packet framing, complete reply draining, checksums, bounded directory discovery, command diagnostics and hardware timing guards. TSPico v2.x SYNC must not be sent to the original 1.00 interface. Passing a functional model is not permission to remove delays required by physical hardware.
  • Disk and persistence tools: the storage reference separates raw file access, a mounted CP/M service volume and a RAMDisk snapshot. It covers 160/320KB Oliger-compatible media, saved descriptors and complete page sets, conversion tools, and failure handling for incomplete or mixed saves.
  • PicoVideo text and ULA+: the graphics skill now describes firmware/selector validation, full 16-bit access to the ULA+ selector/data ports, mode selection, character and attribute memory, bank-aware display capture, scrolling and width changes. It also documents ULA+ palette access and GRB colour packing, including CP/M's ink/paper palette convention. These reusable rules help with other supported ULA+ features without assuming that every display mode or register exists on every firmware.

The references link the TSPico storage skill, cartridge-development skill and graphics and animation skill. Hardware observations, source inspection and emulator/model checks are identified separately so future work can build on the evidence accurately.

Original TSPico 1.00 has booted and run the games on hardware. Many failure cases, TSPico v2.x SD services and PicoVideo 4.2 are tested with native Z80/protocol models; see the validation notes for limits. This release is CP/M 2.2, leaving a separate path for future 3.x work.
