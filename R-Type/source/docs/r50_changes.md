# r50: movement, snake geometry, title ownership, boss delta experiments

The game retains its key-definition flow. One-pixel initial taps remain; after three held samples, sustained motion advances three pixels before one background-aware publication. This raises travel speed without rendering three times. Scratch is55bytes per plane atF790..F7FD, with up to11 row addresses atF800..F815. The actual union height is8+abs(newY-oldY), so horizontal moves process8rows. The earlier fixed9-row assumption failed an accelerated vertical test and was corrected before packaging. The894-tick patterned-background test preserves shared pixels and both retained planes and distinguishes real pixel collision from merely sharing a cell.

The old L1 conversion resized a100x30 arcade chain into each24x24 native frame. R50 extracts a single31x30 joint, converts it at24x24, supplies orientation siblings and adds short bone links aligned to the native joins. These links/rotations are authored adaptations of the original joint, not additional extracted arcade animation cels. Native dimensions, pointers and movement anchors stay unchanged. BOOT initially stores game state in DOCK1, unlike separately loaded level1; the converter therefore reads the authoritative E000 palette mirror for both. An intermediate attempt using BOOT2000 as a palette produced empty cyan marks and was rejected. The normal level1 route now captures actual joints linked along the diagonal. Palette/style can be refined independently of spacing.

The title garbage came from a real ownership collision: bank7E400..F8FF formerly held suffix/phase atlas data, then the player engine/phase/backing caches reused that range. Old title checks covered the earlier pre-integration build and missed this. R50 creates the selected suffix/phase in title-owned HOMEA600/A750 scratch from intact DOCK4 logo data. It restores the scratch before game entry. All116 bitmap and ECM states are checked via the actual disk loader, with player executable/phase cache immutability guards. Lesson: validate the final packaged memory map and title-to-game handoff, not merely each earlier component; lifetimes need explicit owners and overlap checks.

The first boss experiment is a native fixed-pose comparison, Bellmite_relocatable_deltas_TS2068.tap. Eight consecutive actual25-part actor arrangements are composed using r49, encoded once, and replayed forward/backward at selectable origins. It costs26587stream bytes plus16pointer bytes.105 native cases at7origins,105 live completed frames, pause/preset controls and120519 shared-pixel write checks pass. Mean cached publication193830cycles versus2130180cycles for original25 source draws; composition/encoding is excluded from the cached timing. It is not an arbitrary-state boss solution or whole-game FPS comparison.

The second experiment explicitly permits arbitrary arrangements from the start. boss_dynamic_renderer.mjs caches individual sprite-local samples by cel, horizontal phase, orientation and row. They contain no backdrop or destination. An object change invalidates its old/new cell coverage; all intersecting parts are recomposed in current priority order. Legal8x1 pairs are selected after overlap. Only final paired-plane differences are published. It supports insertion, removal, independent animation, depth changes, both flips, negative/offscreen positions and a changing star backdrop. The interactive index.html lets the user drag and rearrange independent spheres/core; no complete boss-frame atlas is used.

100 arbitrary arrangements compare dirty recomposition with a full reference, then execute the resulting stream using the real Z80 publisher. Shared pixels remain present during writes. Mean298dirty cells of6144 and21604publication cycles are sample-specific; composition/encoding is on the host and is excluded. This is a host-side architectural prototype plus native publication validation, not a native compositor or game integration. Its interactive UI script passes DOM/canvas test-double execution; preview.png is that rendered canvas, not hardware or a gameplay capture.

For native integration, cache packed phase coverage/row pairs and movement damage stencils; never cache scene-dependent XOR as an object-only invariant. Recompose shared cells once, including stationary intersecting parts and background damage. Use clipping, ownership/version guards and a full recomposition fallback for uncertain states. Track composition, stream generation, publication, bank switches and interrupts separately. Limit active phase variants or use small LRU caches; do not blindly store every object's every phase/flip. Budget the read-only64KB cartridge separately from the full512KB resident disk layout. The old stock cartridge is unchanged in this release. Boss experiments remain outside gameplay until the complete native path earns a measured win.
