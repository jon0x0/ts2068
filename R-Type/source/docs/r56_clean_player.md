# r56: stale boss pixels around the player

The native renderer treats ownership metadata as authoritative. A cell marked empty may retain bitmap/attribute garbage from an earlier boss frame. The player overlay correctly treated that as empty when taking its backing snapshot, but its exact-mask publication deliberately preserved pixels outside the ship mask. Marking that cell as player-owned (3) then made the native copy publish the entire cell, including those stale pixels outside the ship. The resulting fragments lasted until a later empty-cell clear. Earlier r54 tests protected changes outside the ship masks but did not exercise this ownership change through the real slow native copy.

The fix sanitizes only metadata 0/3 bytes in the existing player backing patch before overlay composition. Occupied cells are unchanged. The patch top is aligned to eight raster lines, so a native full-character copy cannot read unsanitized lines above/below a ship that crosses a character boundary. Patch movement bounds, exact-mask publication, player input/motion and independent projectile updates remain intact.

The final publication already saved the clean backing under the current ship into OLD. Copy cleanup now transfers those same 64 bytes into WORLD rather than sampling them again one byte/bank switch at a time. This recovers code space and reduces cleanup work; the renderer is 2423 bytes versus 2427 in r55. No extra scan runs per player tick. Existing player tick mean/max cycles are unchanged in the component test.

The captured L5 native copy reproduction compares a clean reference copy against the IRQ-moving player variant. Neutral plus eight directions and five IRQ intervals (45 cases) reproduce 695 unwanted byte changes in r55, zero with r56. Audio/input polling and native moving-star routines are stubbed in this focused comparison. Two cases lose one existing star byte inside the swept ship footprint, which is recorded separately and is not claimed fixed. The four initial right-moving timings compare exactly after the fix.

112 backing-cache cases cover top/bottom/left/right edges and fine phases with actual varied data and mixed metadata: 23936 occupied bytes preserved, 47744 empty bytes sanitized, 616448 bytes outside the patch preserved. The full old live-world mask test was strengthened to use real varied bytes (its inherited Buffer.from generator had ignored the callback). Native graphics, boss dimensions/shaders, joystick/key mapping, audio and disk/cache code are byte-identical to r55; only E400..ED7F changes in each asset region.

Diagnostics under build/diagnostics/player_ghost_r56: captured HOME/DOCK files/state; copy_comparison.json and copy_clean_comparison.json; ghost_before.png, ghost_after.png and ghost_comparison.png are actual emulator-buffer renders, not physical hardware photographs. The comparison zoom shows the old fragments beside the ship removed. The comparison crop was visually inspected; the full before/after frames are retained.
