# r57 projectile sequencing and bounded fire input

The user reports a genuinely out-of-sequence single projectile on L5/PicoVideo, plus rapid firing continuing for seconds after release. This is not classified merely as a pause/resume symptom. The exact reported backward display has not been reproduced in emulation. Emulator single-shot coordinate, framebuffer, raster and visible-byte-write traces are forward ordered. The changes address specific unsafe ordering/replay paths as well as the separately reproduced stalls and backlog.

Input scanning was observed to return with IFF1 enabled inside the IRQ handler. The handler stores only one interrupted stack/bank context. A controlled second source pulse after an EI-returning scan is accepted by r56 and the original context fails to return within 100000 instructions. r57 masks the SCLD periodic interrupt source across the entire handler, and unmasks it under DI just before restoring the original bank/stack/registers. The same second-pulse test is blocked and returns correctly. This demonstrates a real re-entry hazard; it is not a recording of the user's exact PicoVideo event.

The projectile loop runs during player backing preparation. Actual screen copies advance projectile coordinates without drawing into a changing copy. Copy completion republishes the current bolt position without an extra movement step. Republish validates type and coordinates against the live native slot, so a cleared/reused slot cannot paint a stale cached position. The gateway preserves its caller's F4 mapping and alternate AF, allowing safe calls from the bank7 player cleanup. AF' holds the bank map temporarily; private projectile helpers must not exchange AF'.

Only the latest fire release is pending. Normal releases can be dispatched by the busy IRQ path, rather than waiting for a slow world update. A blocked short release expires after eight capture polls; twenty blocked rapid taps leave one pending release and then none, with no catch-up after unblocking. Charged release handoff remains native. Under load fast inputs can coalesce; this is deliberate freshness rather than a replay queue. Native sound and selected game controls are retained.

The existing normal/spread steps and artwork are unchanged. A captured single flight previously stretched beyond 200 display refreshes; the new open-flight route reaches the far edge within 90. This test bypasses only projectile collision queries so scenery cannot terminate the shot.
