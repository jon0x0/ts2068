# r62 Force interaction and immediate preload feedback

The independent pixel renderer had removed the native player draw at 9560. That draw also published the player ID into the native collision/ownership grid. IRQ rendering marks a fine-position footprint, but it does not reliably supply the coarse logical tags at the point where the Force and pickups run. A controlled native Force fixture remained detached without the tag; stamping it made the unchanged native docking routine attach immediately.

The new 61-byte HOME helper at FDC3 runs after the existing player synchronization gateway and before native 9559. It checks active state and native coordinates, writes ID3 only into empty cells of the original four-cell footprint, and then continues through the normal player logic. It does not draw pixels, invent pickup rules, overwrite terrain owners, or bypass the native docking routine. It preserves the independently clocked player/projectile engines and the user's key definitions. Native docking, electrical secondary-action detach/recall, and weapon-pickup upgrades are tested on levels 1, 3, 5 and 6 using controlled spawned objects in actual gameplay. This is not an unassisted carrier-kill playthrough.

HOME FDC3..FDFF belongs to the old popup/delay/clear routines already relocated to cartridge code. The final lifetime scan additionally found counted-delay entry FDEB, not just FDE9. Five common callers, C059, and four original high-tail callers now use 0002, preserving the caller's B count; FDE9 uses 0000 for B=0. FDAA's popup interior entry remains redirected to 000D. The boot RTCORE high tail installs the new helper; the runtime gateway's FB98 continuation is the only changed bank7 code. Direct CALL/JP references into the reused high range are rejected by the packager. This raw byte scan is a bounded check, not an exhaustive reachable-code proof; the original partial disassembly identifies the actual counted-delay callers.

Shift-L saves then zeros AY registers8/9/10 immediately, clears the beeper, and displays LOADING before the long selector guard waits. The message uses standard attribute cells with identical ink/paper; it leaves both the game bitmap and ECM plane intact. The unused standard attribute plane becomes waiting-screen scratch. The detailed logo/progress UI follows after the HOME snapshot. Stored volumes, registers, stack, active banks, game bitmap and ECM resume afterward. If all levels are resident, the request remains a no-op.

The early message is a separate 63-byte routine/data block: generic source DOCK1:3E00; L5 source DOCK5:A400, outside its copied hotkey prefix and before A4AE. The L5 prefix is exactly1024bytes, ending before the 7F00 snapshot bootstrap. No new helper occupies E350: that address is the live generic boss table. A provisional placement there was rejected after the extended L3 write guard caught invalid compositor output at A331; it is not evidence reproducing the user's r61 glitch. Final static contracts preserve all r61 bank7 bytes E000..FB97 and FB9B..FFFF, including boss tables, histories, player/projectile engines and palette IDs. Only FB98..FB9A change to the new HOME continuation.

The ordinary L3 diagnostic follows the bottom edge (player y roughly133..152), firing with scripted movement for2000worldupdates. It bypasses damage only for diagnostic continuity, guards executable writes and global source tags, and saves completed world captures. It cannot by itself identify the user's hardware-only terrain-edge glitch. That issue remains open pending a matching image/reproducer; do not claim it fixed by the Force change.

Level6 minor descriptors5..17 retain native Spectrum art; its boss descriptors18..33 have earlier arcade-derived assets.
